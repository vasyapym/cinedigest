# cinedigest — вечерний кинодайджест СПб

Раз в день собирает сеансы семи кинотеатров Петербурга («Дом кино», «Родина», «Аврора», «Художественный», «Ленфильм», Out Cinema, «Мираж на Большом») на ближайшую неделю и пишет: одностраничный сайт (`docs/index.html`), текстовую выжимку (`docs/digest.txt`), снимок данных (`docs/screenings.json`, `docs/status.json`) и, если настроено, пушит сводку в Telegram. Всё читается по файлам, тесты не трогают сеть.
Страница живёт на GitHub Pages (ветка `main`, папка `/docs`): Settings → Pages → Deploy from branch → main /docs. Обновляется трижды по утрам Actions (06:17 / 07:17 / 08:17 МСК): сеансы с 18:00, «весь день» и фильтры по площадкам — чекбоксы без JavaScript; каждый день окна — отдельная статическая страница (docs/index.html = сегодня, docs/YYYY-MM-DD.html = остальные дни; переключение — обычные ссылки, страницы вне окна удаляются при сборке); площадка каждого сеанса — цветной бейдж с названием над строкой фильма; ночные показы стоят под предыдущим днём с бейджем «ночь на чт». JS на странице — только localStorage для переключателей, приглушение прошедших сеансов и баннер устаревшей страницы.

## Фильтр «нероссийские»

Включённый фильтр скрывает фильмы, среди стран производства которых есть Россия, в том числе копродукции. Учитываются «Россия», «Российская Федерация», RU и RUS без учёта регистра, пробелов и разделителей списка. СССР, SU и Soviet Union не считаются Россией. Если страна неизвестна, строка не исключается этим фильтром; остальные фильтры продолжают действовать. Состояние фильтра живёт до перезагрузки страницы: скрывающий фильтр сознательно не восстанавливается из `kino.toggles` и вычищается из неё при следующей смене любого чипа.

Страна площадки сохраняется без изменений. Для HTML недостающая страна может быть скопирована из того же окна показа при совпадении названия после `posters.norm()` и совместимом годе. Разные известные годы считаются разными фильмами; строка без года принимает данные только при единственном непротиворечивом кандидате. Конфликтующие наборы стран блокируют перенос. Уточнения в названиях не удаляются, нечёткий поиск не используется. Обогащение локальное, без сетевых запросов; исходный снимок, `digest.txt` и Telegram не изменяются.

Межплощадочное заполнение в пределах окна дополнено локальными свидетельствами из закоммиченного `docs/posters.json`: CLI передаёт внутреннюю карту кеша в HTML-рендер, который читает страны без токена и сети. Эти свидетельства участвуют в тех же проверках совпадения и конфликтов, а не перезаписывают страну площадки. В записи кеша `country` хранит названия стран производства из TMDB movie details, `country_at` — дату получения этих данных, `country_via` — отметку их происхождения из TMDB.

Для строк без года `countries.identity_hints()` восстанавливает единственный известный год по нормализованному названию из окна и дополнительных свидетельств; датированные записи учитываются даже без страны. При нескольких годах подсказка не выдаётся, исходный год строки не меняется. В командах `run` и `posters` при наличии `TMDB_READ_TOKEN` эти подсказки передаются в `posters.resolve(..., year_hints=...)`; офлайн-команда `render` резолвер не вызывает.

## Постеры (TMDB)

Постеры берутся из TMDB (developer-тариф, некоммерческое использование; условия и их разбор — docs/tmdb-image-use.md).

- Ключ: секрет/переменная окружения `TMDB_READ_TOKEN` (API Read Access Token). Без неё запуск пишет строку в лог и рендерит то, что уже лежит в кэше.
- Кэш метаданных: `docs/posters.json` — один поиск на фильм (название + год), ≤150 фильмов за запуск; найденное обновляется через 150 дней, ненайденное — через 14; записи старше 180 дней удаляются при каждой записи файла (правило «кэш не дольше 6 месяцев»).
- Локальные байтовые копии: скачиваются в `docs/posters/<имя>` (имя — проверенное базовое имя `poster_path`), страница вставляет именно их (`src="posters/<имя>"`), а не картинку с `image.tmdb.org`. Скачивание дедуплицируется по `poster_path`, за запуск ≤150 файлов, лимит неудач (3) останавливает этап до следующего запуска; файл публикуется атомарно (tmp + rename), сорванная загрузка не портит уже лежащие байты. Поля `file` и `file_downloaded_at` в записи кэша держат имя файла и дату скачивания.
- Жизнь байтов независима от метаданных: возраст файла считается по `file_downloaded_at`, обновление метаданных не «омолаживает» файл; постер показывается, только если файл есть на диске И его дата не старше 180 дней — иначе постера нет вовсе, подмеса с CDN не происходит. Просроченные записи и файлы подчищаются и в фазе `posters`, и при офлайн-доставке (`render`/доставка запускает ту же чистку без токена).
- Ручные правки: `docs/posters-overrides.json` (`null` — без постера, `{"tmdb_id": N}` — конкретный фильм, `{"poster_path": "/x.jpg"}` — конкретный файл; его байты тоже скачиваются локально).
- Первичное заполнение без повторного обхода площадок: `TMDB_READ_TOKEN=… python -m cinedigest posters --out .`
- Атрибуция (логотип `docs/tmdb.svg` с официальной страницы логотипов, ссылка на themoviedb.org и дословное уведомление) выводится в подвале каждой страницы, где есть хоть один постер. Картинки отдаются из локальных файлов `docs/posters/` без обработки; права на сами постеры остаются у дистрибьюторов.
- digest.txt и Telegram остаются простым текстом без постеров. Фильмы без года также участвуют в поиске постеров: запрос отправляется без параметра года, а результат принимается только при единственном кандидате TMDB с корректным идентификатором. Год в строках сеансов не изменяется; ключ такой записи кэша заканчивается на `|any`. Когда появляется год или подсказка года, недатированная запись удаляется, а датированная проверяется заново. Для известных служебных суффиксов названия выполняется не более одного дополнительного поиска с очищенным названием; для датированных фильмов сохраняется допуск ±1 год и требуется точное совпадение очищенного названия.
- Deleting docs/posters.json and docs/posters/ purges the served poster cache. TMDB API debug snapshots are separate; complete removal also requires deleting applicable local snapshots and retained Actions artifacts. Remove the token and relevant overrides to prevent repopulation.

## Команды

```sh
.venv/bin/python -m cinedigest run                  # всё: fetch 7 дней + страница + digest + telegram
.venv/bin/python -m cinedigest run --out docs       # вывод под указанный корень (docs/ и snapshots/ под ним)
.venv/bin/python -m cinedigest run --days 3         # окно в 3 дня
.venv/bin/python -m cinedigest run --date 2026-11-07        # один день
.venv/bin/python -m cinedigest run --only rodina,domkino    # перечисленные площадки
.venv/bin/python -m cinedigest run --no-telegram    # без пуша
.venv/bin/python -m cinedigest run --print          # напечатать текст для Telegram в stdout, не отправляя
.venv/bin/python -m cinedigest render               # пересобрать страницу+digest из сохранённого снимка, без сети
.venv/bin/python -m cinedigest fetch --venue rodina --date 2026-11-07 --save /tmp/raw   # сырые ответы одной площадки
```

Коды выхода: `0` — все площадки ok; `2` — хоть одна не собралась (в т.ч. устаревшие данные с прошлого запуска); `1` — падение. Площадка, у которой ничего не собралось, замещается сеансами предыдущего снимка с пометкой «данные с прошлого запуска».

## Переменные окружения

- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — обе заданы → сводка на сегодня уходит в Telegram; иначе шаг пропускается с записью в журнал.
- `CINEDIGEST_PAGE_URL` — последняя строчка телеграм-сообщения (ссылка на страницу).
- `CINEDIGEST_REPO_URL` — ссылка «код» в подвале страницы.

Секреты никогда не попадают в репозиторий; в Actions задаются как secrets.

## Как устроено

- `cinedigest/model.py` — типы `Screening`, `VenueStatus`, `Snapshot`, порядок `VENUES`, вечер с 18:00, ночь до 06:00 сидит под предыдущим днём.
- `cinedigest/venues/<venue>.py` — по модулю на площадку: `ID`/`NAME`/`DAILY` + сетевой `fetch(http, days)` и чистый `parse(raw, days)`. Сырые ответы складываются в `snapshots/<run-id>/<venue>/<label>`.
- `cinedigest/pipeline.py` — одно окно: fetch+parse каждой площадки, политика ошибок (падение площадки не валит страницу), перенос старых данных ≤72 ч, правило «ноль без маркера „сеансов нет“» для ежедневных площадок.
- `cinedigest/render.py` + `templates/index.html.j2` — контекст и одна Jinja-страница (CSS-чекбоксы; JS только для localStorage, приглушения времени и перехода ко дню).
- `cinedigest/render_text.py` — тот же материал в тексте: `digest.txt` и тело Telegram (разбиение по пустым строкам и строкам, части с «(i/n)»).
- `cinedigest/deliver.py` — запись `docs/index.html` и `docs/digest.txt`, Telegram-пуш по частям (plain text, без parse_mode).
- `cinedigest/cli.py` — `run` / `render` / `fetch`.

## Как добавить площадку

1. Скопируйте любой модуль из `cinedigest/venues/` под вашу площадку и заполните `ID` (ключ в `model.VENUES`), `NAME`, `DAILY`.
2. `fetch(http, days)` → список `(label, body)`; только сеть.
3. `parse(raw, days)` → список `Screening`; без сети, падает на неожиданной разметке — её поймает правило «странного нуля».
4. Зарегистрируйте площадку: ключ в `model.VENUES` и модуль в списке `cli.DEFAULT_VENUES`; положите фикстуру ответа в `tests/fixtures/<venue>/` и напишите тест на `parse` по ней.

## Тестирование

```sh
.venv/bin/python -m pytest -q
```

Тесты рендера, конвейера и площадок работают на сохранённых ответах (`tests/fixtures/`), сеть не вызывается.
